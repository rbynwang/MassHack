A map of this repository for coding agents (Kiro, Claude, Copilot, and others) and new teammates. It says what each file does, how data flows, which numbers are current, and the rules the team set. If you change behavior, update this file.

## 1. What the project is (30 seconds)

**GridCollective Boston** (MassHack / Hackachusetts 2026, Track 3 Climate Tech). It simulates 116 Boston buildings acting as one collective on two real peak days (winter 2026-01-30, summer 2025-06-24):

```
Grid signal (ISO-NE price + load, DR events)
  → Collective coordinator   pools offers, assigns tasks, checks rebound peaks, splits revenue
  → Trust layer              hard limits in code + Ed25519 signed, hash-chained receipts
  → Member agents            forecast load (ML) → plan battery (LP) → offer flex with a cost
  → Buildings                HouseZero + BPL Central (measured), 25 civic, 9 large retail, 40 small business, 40 homes
```

The machine-learning core:
- **Forecast:** per-building LightGBM quantile models (P10/P50/P90) with a calibrated band.
- **Action effects:** a model of what each building mode does to load, trained on paired runs.
- **Plan:** a battery planner that re-plans every hour over several forecast scenarios (stochastic MPC).

A JEPA-style world model is trained and evaluated alongside the others. Today it is less accurate, and the pipeline reports that.

## 2. Hard rules (set by the team, do not break)

1. **Data window:** only **2025-05-01 to 2026-06-01** (America/New_York). `tests/test_period.py` enforces it.
2. **Weather:** HouseZero's measured weather is the **only** weather source. ComStock building designs are used only as physics templates; none of their 2018 timestamps or weather are exported.
3. **Commits:** author is `Xuening Wang <wxnrobin@gmail.com>`. No AI co-author or attribution lines in commits or PRs. Push only when the team asks.
4. **Honesty in results:** synthetic and template members are labeled as such. Batteries for civic and business members are hypothetical (2 h at 30% of peak). Bills cover single peak days and are not annualized.

## 3. Run it

```bash
pip install -r requirements.txt
python run_all.py --reuse                    # ~1 min: reuse app/forecast_cache.pkl, re-simulate, write app/public/demo.json
python run_all.py                            # ~20 min on 2 CPU cores: full retrain + evaluation + simulation
python eval/planner_variants.py app/forecast_cache.pkl   # planner check -> eval/planner_summary.json (shown on the demo after the next run)
python make_results.py                       # RESULTS.md from app/public/demo.json
python eval/make_evaluation.py               # EVALUATION.md (before vs now)
python -m http.server -d app/public 8000     # demo at http://localhost:8000
python -m pytest -q                          # 12 tests
```

Run commands from the repo root. Data defaults to `data/model_inputs`; override with `--data` (run_all) or the `MASSHACK_DATA` environment variable (eval scripts).

## 4. File map

### Top level
| File | What it is |
|---|---|
| `run_all.py` | **The pipeline.** Loads data → builds 116 agents → whole-week split → trains world model, per-building LightGBM, no-weather ablation and paired-difference action models → calibrates bands → evaluates on ~104 held-out days → picks the effect model for each action → refits final planner models on all days except the peak weeks → caches peak-day forecasts → simulates both peak days and the temperature what-if → Boston projection → writes `app/public/demo.json`. `--reuse` skips training. |

## 5. Current numbers (from RESULTS.md / EVALUATION.md)

- **Forecast, ~104 held-out days:**
  - whole community: 4.0% error, 3.7% on the peak hour;
  - civic / retail / small business: 6–7%; BPL Central: 5%; HouseZero: 9%; single homes: 32%;
  - the P10–P90 band covers 80% of hours (target 80%).
- **Action effects (shape match, 1.0 = perfect):** pre-cool 0.97, load shift 0.66, EV delay 0.58 (plug-in timing is random).
- **Battery savings captured** (share of the perfect-foresight maximum): winter 78%, summer 66%. One forecast line gets 62% / 47%; a perfect forecast gets 99% / 102%.
- **Peak days, collective vs no battery:**
  - community bills −9.3% (winter) and −5.3% (summer);
  - community peak 14,089 → 13,215 kW (winter) and 13,969 → 13,733 kW (summer).

## 6. Known limits and next steps

- 114 of 116 members are physics templates or synthetic. Only HouseZero and BPL Central are metered.
- The world model is less accurate than LightGBM for normal load and for every action. It stays in the evaluation.
- In winter, the collective's single highest hour is about 1% above batteries acting alone. It moves from run to run.
- Most value left: hourly re-forecasting using the latest meter reading. The planner with a perfect forecast reaches about 100%; ours reaches 66–78%.
